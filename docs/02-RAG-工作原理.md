# RAG 的工作原理

RAG 是 Retrieval Augmented Generation 的缩写，中文通常叫「检索增强生成」。
它的核心想法很简单：模型参数学不完你的私有资料，那就先检索、再让模型拿着检索结果作答。

## 五个步骤

1. 加载：把 txt、md、pdf、docx 等文件读成纯文本，并保留来源、页码这类元数据。
2. 切块：长文本按语义边界切成几百字的片段。切块太大，检索不精准；太小，上下文不够。
3. 向量化：用嵌入模型把每个片段编码成向量，存进向量数据库。语义相近的文本，向量距离也近。
4. 召回：用户提问时，问题同样被编码成向量，在库里找出距离最近的若干片段。
5. 生成：把召回的片段连同问题一起放进提示词，让模型只依据这些资料作答。

## 为什么切块参数很关键

常见的默认值是 1000 字符、重叠 200 字符。但如果文档本身只有一千字，
这个配置会切出唯一一块，检索环节等于没有生效——所有问题都返回全文，模型也就无从取舍。
更实用的取值是 500 到 800 字符，重叠 100 到 150 字符，并且按中文标点优先切分，
而不是硬按字符数截断。

## 什么时候 RAG 会失效

- 召回没命中：问题用词和文档用词差异太大，向量也拉不回来。解决办法是加混合检索或做查询改写。
- 块被切碎：答案横跨两个块，召回只拿到一半。解决办法是加大重叠或做父子块检索。
- 模型不听指令：给了资料仍然自由发挥。解决办法是降低 temperature，并要求逐句标注引用编号。
