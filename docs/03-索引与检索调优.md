# 索引与检索调优

## 增量索引怎么判断要不要重建

飞链给每个文档算一个内容指纹（sha1）。同步时比对三件事：

- 文件是否新增：库里没有这个路径，就切块写入
- 内容是否变化：指纹不同就删掉旧块、写入新块
- 文件是否删除：manifest 里有、磁盘上没有，就把它的块一并清掉

指纹没变就跳过，所以第二次执行 index 通常是「新增 0，跳过 N」，不会重复消耗算力。

如果切块参数或嵌入模型发生变化，manifest 里的签名会对不上，
此时会自动整库重建，避免新旧向量维度不一致导致检索报错。

## 检索条数怎么定

top_k 太小，答案缺料；太大，噪声淹没重点，还会撑爆上下文。
经验值：单点事实型问题用 3 到 4；需要综合多处信息的问题用 6 到 8。
配合相关度阈值（score_threshold）可以先把明显不相关的结果挡掉，
例如阈值设 0.2，低于这个分数的片段就不进上下文。

## similarity 与 mmr 的选择

- similarity：纯按向量相似度取前 k 条，速度快，适合问题聚焦时
- mmr：在相似度和多样性之间做平衡，适合问题包含多个子话题、需要覆盖不同角度的场景
  代价是要多取一些候选（fetch_k），计算稍慢。

## 常见症状与对策

| 症状 | 大概率原因 | 对策 |
| --- | --- | --- |
| 答案总是答非所问 | 切块过大或 top_k 过小 | 缩小 chunk_size，提高 top_k |
| 答案只覆盖问题的一半 | 答案被切断 | 提高 chunk_overlap |
| 检索为空 | 索引没建或目录配错 | 执行 feilian index，检查 DOCS_DIR |
| 引用编号对不上 | 模型没遵守约束 | 降低 temperature，提示词强调标注 |
